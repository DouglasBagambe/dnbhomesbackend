# Final release hardening

Public search uses the existing Mongo text index for candidates and requires each meaningful literal query term across the indexed title, description and location fields. Queries are normalized, limited to 100 characters/12 distinct terms, and escaped; controlled property-noun plurals are supported. Searches rank normalized exact titles, phrases and title/location matches before text score. Explicit price, oldest and popular sorting remains available; stable ID tie-breaks preserve pagination. Public queries have a 3-second database deadline. No search service or index migration is required.

New viewing creation returns a 256-bit random `statusAccessToken` once. Only its SHA-256 hash is stored (excluded from ordinary selects). `GET /api/v1/bookings/:id/status` accepts an ID/reference plus `X-Viewing-Token`, returns only reference/scheduledAt/status/updatedAt, uses no-store and 60 requests/minute, and gives the same 404 for missing/wrong/unknown authorization. Tokens are redacted from request logs. Legacy records without a token cannot sync; reference alone never authorizes access. Do not backfill insecure tokens or disclose guest/admin data.

Media: JPEG, PNG, WebP, AVIF; MP4 and WebM. At most 10 files/request, 10 MiB/image, 50 MiB/video, 100 MiB aggregate file data/batch (1 MiB multipart overhead allowance). Known oversized bodies are rejected before parsing. Unknown-length multipart bodies are bounded by the per-file/count limits before the aggregate check. Files spool to temporary disk, are uploaded sequentially, and are cleaned on success/failure. A failed batch rolls back its newly created assets, not previous batches. Properties accept at most 40 media, never truncate, and covers must be images. Updating media without an explicit cover selects its first image or clears the cover when none remain.

Admin needs a direct upload path because Vercel Functions have a 4.5 MB request-body limit. The authenticated, HttpOnly/same-origin Admin proxy mints `POST /admin/media/tickets`. The browser uploads one bounded batch to `POST /media/uploads` with `X-Media-Upload-Token`; no Admin JWT is exposed. A grant is 256-bit, hash-only, single-use/atomically consumed, expires after 120 seconds, binds the Admin origin and checks the active Admin and token version again. Existing roles and exact CORS allowlists still apply. Deploy this API before the matching Admin UI; configure only the exact approved Admin preview origin. Do not relax CORS to accommodate arbitrary previews.

QA reuses property `6aca1225ca3d4ce6f2209da4` only in `homes_preview`, with `qa:media-heavy`/`preview` tags and unverified status. Synthetic, labelled QA media are not genuine inventory. The existing 50 showcase records and fixed 17 assets are preserved. Render local media uploads are temporary and may disappear on redeploy; real launch uploads require configured S3/R2-compatible durable storage. No storage infrastructure was migrated and no production database was touched.

Validation: `npm ci`, `npm run check`, `npm test`, `git diff --check`. Integration tests cover tokens/privacy/status transitions, grant expiry/origin/replay, media limits/cleanup/rollback/cover removal and search/filter/pagination relevance.
